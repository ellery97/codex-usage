# 压缩日志扫描验证记录

验证日期：2026-10-22。环境：macOS arm64，Node.js v24.18.0。所有性能数字来自合成日志，不能直接外推为真实历史的耗时。

- 本地 Node.js 24.18.0：`npm run check`，148 项测试通过。
- `git diff --check` 通过。CI 覆盖 Linux、macOS、Windows，以及 Node.js 22.15.0、22、24；远端结果以 PR 检查为准。
- 受控阻塞测试验证已有/空索引均可先提供 HTTP 查询；覆盖失败隔离、保留旧索引、重试、发布冲突、跨进程查询竞争和退出取消。
- 浏览器用合成数据验证：补扫中筛选可用、失败详情与重试按钮可见、恢复后当前筛选自动更新且告警消失。

- Zstd 测试覆盖连续帧、可跳过帧、UTF-8 分块、无末尾换行、流式帧、多块、校验和、截断、取消及原生解压错误。

## 扫描和 API 性能

每种场景独立进程运行 5 次，以下为各指标的中位数。64 个普通文件与 4 个压缩文件，每文件 40 个用量事件；每个压缩文件额外包含 8 MiB 的无关日志。扫描时持续请求 `/api/usage`。

| 场景 | 扫描耗时 ms | 源文件读取 B | 解压后处理 B | API 请求中位数 ms | 单轮最慢请求的中位数 ms | 进程峰值 RSS MiB |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 首次建索引 | 74 | 528281 | 34113272 | 2.42 | 11.33 | 129.2 |
| 未变化重跑 | 23 | 0 | 0 | 25.08 | 25.08 | 101.9 |
| 只追加普通日志 | 27 | 199 | 199 | 24.79 | 24.79 | 101.7 |
| 只修改一个压缩文件 | 33 | 1366 | 8397807 | 24.89 | 24.89 | 102.3 |

峰值 RSS 使用独立进程的 `process.resourceUsage().maxRSS`，包含夹具创建、预索引（适用时）和本轮扫描。基准不启用显式 GC。API 测量包含首次计价与聚合；它也会影响同进程扫描的墙钟耗时。

硬性条件均通过：未变化重跑读取/解压均为 0；普通追加仅处理 199 B，没有重读压缩日志；首次补扫完成前已成功返回 HTTP 查询。

## 内存随无关日志体积变化

保持用量事件数不变，无关日志每行约 4 KiB，只增加行数。每种体积运行 5 次：

| 无关日志 MiB / 压缩文件 | 完整处理量 MiB | 进程峰值 RSS 中位数 MiB |
| ---: | ---: | ---: |
| 8 | 32.5 | 129.2 |
| 32 | 128.5 | 133.3 |
| 128 | 512.5 | 141.9 |

该样本中内存未随完整解压体积线性增长。内存仍受最长单行、Zstd 窗口和实际用量事件数量影响。

| 场景 | 基线 ms | 本次 ms | 增量 ms |

## 复现

```bash
npm run check
npm run benchmark:scan
node bin/benchmark-session-scan.mjs --plain-root=/path/to/baseline
node bin/benchmark-session-scan.mjs --plain-root=.
```

扫描基准只在系统临时目录创建数据，退出后自动清理；`--runs` 至少为 5。基线目录需是 `0e8c478` 的独立检出或归档。
